# FR-K. LLM 위키 (LLM Wiki)

사용자가 자료(딥 리서치 결과·MD·PDF·이미지·YouTube)를 주입해 계속 키우는 개인 지식 위키.
좌측 위키 트리 + 우측 RAG 채팅(위키 출처/웹 출처 표시). 위키에 내용이 없으면 Tavily 검색으로 답하고 그 답을 위키에 자동 저장.

## FR-K1. 메뉴 및 접근 제어

- **FR-K01** 사이드바에 "LLM 위키" 메뉴(`/llmwiki`)를 추가한다. 표시 조건은 `llmwiki.read` 권한 보유. 접근 제어는 서버 측 `require_permission("llmwiki", ...)`로 수행하고 프론트엔드는 권한 기반으로 메뉴를 렌더링한다. 사용자·프리미엄 사용자·운영자 역할 모두 시드로 `llmwiki` 권한(create/read/update/delete)이 부여된다(소유자 스코프).

## FR-K2. 주입

- **FR-K02** 위키에 자료를 주입할 때 **딥 리서치 결과**를 넣을 수 있다. 주입 대상은 완료된 딥 리서치 세션의 최종 보고서(`kind=final`)이며, 페이지 본문은 `# <세션 제목>` + 보고서 본문으로 생성된다. `source_ref`는 세션 ID이며, 세션은 호출 계정이 소유한 것이어야 한다(아닐 시 403).
- **FR-K05** 주입 소스는 **딥 리서치 결과·이미지·PDF·YouTube·MD 파일**이며 **복수 동시 주입**이 가능하다.
  - **MD**: 파일 텍스트를 그대로 페이지 본문으로 사용(첫 `# ` 줄을 제목으로, 없으면 파일명).
  - **PDF**: `pypdf`로 텍스트를 추출해 페이지 본문화, 원본은 `attachments/`에 보관.
  - **이미지**: 위키에 설정된 LLM의 **비전(멀티모달)** 호출로 이미지를 묘사·분석해 마크다운 페이지를 생성하고 원본은 보관. 비전 미지원 모델이면 400.
  - **YouTube**: URL에서 영상 ID를 추출해 `youtube-transcript-api`로 자막을 fetch(자막 없으면 422)하고 전사 본문을 페이지로 저장. `source_ref`는 영상 ID.
- **FR-K06** 사용자는 언제든 위키에 자료를 주입할 수 있다. 주입은 우측 상단 "자료 주입" 버튼의 다이얼로그에서 파일 드롭존(MD·PDF·이미지 다중)·딥 리서치 세션 선택·YouTube URL을 조합해 제출한다(`POST /llmwiki/wikis/{id}/ingest`, multipart).
- **FR-K11** 주입 다이얼로그의 카테고리 선택에 **"자동 분할 분류 (LLM)"** 옵션(기본값은 "미분류" 유지)을 제공한다. 사용자가 이를 선택한 경우, 위키에 설정된 LLM이 각 주입 소스의 **전체 본문**을 분석해 **주제별로 분할**하여 여러 위키 페이지를 생성한다.
  - 각 분할 페이지의 본문은 LLM이 **원문을 요약하지 않고 해당 주제 부분을 충실하게 발췌**(정보 손실 방지). 단일 주제 문서는 분할 없이 페이지 1개로 자연스럽게 처리된다.
  - 각 분할 페이지의 카테고리는 기존 카테고리 중 주제가 맞으면 그것을 재사용하고(중복 생성 금지), 없으면 LLM이 제안한 간결한 명사구 이름으로 **새 카테고리를 자동 생성**해 배치한다. 예: "LLM FinOps 방법" 문서 → 시멘틱 캐싱 / 프롬프트·컨텍스트 캐싱 / KV 캐싱 등으로 분할되어 각각 별도 페이지+카테고리 생성.
  - 분할은 섹션 최대 12개까지로 제한한다. 매우 큰 문서는 LLM 컨텍스트 한도(약 16,000자) 내로 입력을 절단 후 처리한다(잘린 경우 경고 로그).
  - LLM 호출 실패·응답 파싱 실패·빈 섹션 등 모든 예외 경로는 단일 페이지(원본 보존, 미분류)로 폴백한다.
  - 이미지 소스는 기존 `describe_image` 묘사 결과를 분해 입력으로 사용한다.
  - 자동 분류를 선택했는데 위키에 LLM 제공자/모델이 설정되지 않은 경우 **400 에러**(`"자동 분류에는 위키에 LLM이 설정되어야 합니다"`)를 반환한다.
  - 주입 결과(`IngestResult`)는 `auto_categorized: bool`과 이번 주입으로 새 생성된 `created_categories`를 포함하며, 프론트엔드는 이를 피드백 메시지로 표시한다.

## FR-K3. 위키 구조 및 편집

- **FR-K03** 페이지는 3패널 레이아웃으로 구성된다 — 좌측: 워크스페이스(위키) 목록/생성 + 카테고리 트리; 중앙: 선택한 위키 페이지(조회/직접수정 에디터); 우측: 페이지 기반 질의 채팅창. 패널 경계는 `react-resizable-panels`로 드래그해 크기 조절.
- **FR-K08** 위키는 **사용자별 다중 워크스페이스** 단위(`wiki/<wikiId>/`, 소유자만 접근)이며, 페이지는 **하이라키 구조**로 `wiki/<wikiId>/<카테고리슬러그>/<페이지슬러그>.md`에 저장된다. 카테고리/페이지 트리 매니페스트는 `wiki/<wikiId>/structure.md`에 보관된다. **파일시스템이 진실의 원천**이고 DB(`wikis`/`wiki_pages`/`wiki_chat_messages`)는 검색 인덱스용 캐시로 시작/쓰기 시 동기화된다.
- **FR-K09** 사용자는 카테고리를 **추가/수정/이름변경/삭제**할 수 있다(`POST`/`PATCH`/`DELETE /llmwiki/wikis/{id}/categories[/{catId}]`). 카테고리 삭제 시 하위 디렉토리와 모든 페이지(파일·DB 행)가 함께 제거된다.
- **FR-K10** 사용자는 위키 페이지 내용을 **직접 수정**할 수 있다(`PUT /llmwiki/wikis/{id}/pages/{pageId}`). 수정 시 파일·DB 캐시·structure.md(제목 변경 시)가 함께 갱신된다.

## FR-K4. RAG 채팅

- **FR-K04** 채팅 답변 시 **참조한 출처**를 표시한다. 위키 페이지 출처는 클릭 시 해당 페이지로 이동하고, 웹 출처는 새 창으로 연다.
- **FR-K07** 채팅은 **LLM 자율 ReAct 툴 호출**로 동작한다. 위키 BM25 출처(히트 시 항상 포함)와 함께 질문을 LLM에 주고, LLM이 출처로 답할 수 있으면 바로 답한다. 출처가 부족하다고 **LLM 스스로 판단**하면 `SEARCH: <키워드>` 마커로 **Tavily 웹 검색**을 요청하고, 시스템이 결과를 주입하면 그 정보로 답하거나 **멀티턴**(최대 5회)으로 추가 키워드 검색을 반복한다. 5회 초과 시 수집 정보로 강제 최종 답. 딥 리서치 에이전트(`FR-I05`)와 동일한 ReAct 컨벤션을 따른다.
  - 검색 수행 중엔 `searching` SSE 이벤트(`{query, iteration}`)로 진행 상황을 알리고, 최종 답은 라인 청크 `delta`로 전달한다. 이벤트 순서: `searching`(×N) → `sources`(위키+웹 혼합) → `delta`×N → `done`. 임계치 기반 기계적 트리거(`_WEB_AUGMENT_MAX_SCORE`)는 폐지하고 LLM이 충분성을 판단한다.
  - 웹 결과가 기여한 답변은 **백그라운드 태스크**로 위키에 자동 등록된다. 채팅 응답에 레이턴시를 주지 않도록 `done` 이벤트는 저장 완료를 기다리지 않고 즉시 전송된다(`done.saving_in_background` 플래그).
  - 백그라운드 저장은 **FR-K11 분해**를 적용해 답변을 주제별 다중 페이지/카테고리로 분할 등록한다(독립 DB 세션, fire-and-forget, 예외는 로깅만).
  - 위키 후보 검출은 의존성 없는 순수 Python **BM25**(`core/search.py`)로, 한국어(CJK) 유니그램 + 영문 단어 토큰화, 제목 가중치(3x)를 적용해 상위 5페이지를 검출한다.
