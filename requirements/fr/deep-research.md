# FR-I. 딥 리서치 에이전트 (Deep Research Agent)

## FR-I1. 메뉴 및 접근 제어

- **FR-I01** 사이드바에 "딥 리서치 에이전트" 메뉴(`/deep-research`)를 추가한다. 표시 조건은 `deep_research.read` 권한 보유 (FR-F25 참조). 접근 제어는 서버 측 `require_permission("deep_research", "read")`로 수행하고 프론트엔드는 권한 기반으로 메뉴를 렌더링한다.
- **FR-I02** "딥 리서치 에이전트" 메뉴는 **사용자 역할 이상**(사용자·프리미엄 사용자·운영자)이면 접근할 수 있다. 세 역할 모두 `deep_research.read` 권한이 시드로 부여된다. 권한이 없는 계정(예: 비활성/역할 미부여)은 403 Forbidden.

## FR-I2. 채팅 인터페이스

- **FR-I03** 페이지는 채팅창 형태의 UI로 구성된다. 사용자 메시지와 에이전트 메시지가 교대로 표시되며, 에이전트의 중간 진행 상황(플랜, 스텝 진행, 검색 중 등)과 최종 결과도 동일 채팅 흐름에 렌더링된다.

## FR-I3. 조사 워크플로우

- **FR-I04** 워크플로우는 다음 단계로 구성된다.
  1. 사용자가 조사 대상/질문을 채팅 입력으로 전송한다.
  2. 에이전트가 해당 조사 대상에 대한 **플랜**(조사 항목/스텝 목록)을 생성하여 채팅에 제시한다.
  3. 사용자는 플랜을 **편집**(항목 추가·수정·삭제)하거나 그대로 **승인** 또는 **거절**할 수 있다. 거절 시 조사를 진행하지 않는다.
  4. 승인된 플랜만이 딥 리서치 실행의 입력이 된다. 미승인 상태에서는 조사가 시작되지 않는다.
- **FR-I05** 딥 리서치 실행은 승인된 플랜을 기반으로 다수 스텝을 반복하는 **에이전트 루프**로 동작한다. 각 스텝에서 LLM은 필요 시 **웹 검색 도구**를 호출하여 외부 정보를 수집하고, 수집된 정보를 종합하여 다음 스텝을 계획한다. 중간 진행 상황과 최종 결과는 채팅 창에 **스트리밍**으로 표시된다.

## FR-I4. 모델 선택 및 LLM 백엔드

- **FR-I06** 채팅 세션 시작 시 사용자가 사용할 LLM 모델을 선택한다. 선택 단위는 **세션 단위**이며, 한 세션 동안 선택한 모델이 유지된다. 선택 가능한 모델은 모델 관리 메뉴(FR-J)에서 **활성화**된 모델만 표시된다. 활성화된 모델이 없으면 모델 선택 컨트롤이 비활성화되고 운영자에게 모델을 등록하라는 안내가 표시된다.
- **FR-I07** LLM 호출은 **Ollama Cloud** 또는 **OpenCode Zen API Key** 제공자를 통해 수행된다. 사용자가 선택한 모델이 속한 제공자의 설정(FR-J03)을 백엔드에서 사용하여 호출하며, API 키는 클라이언트에 노출되지 않는다(NFR-S11 참조).
